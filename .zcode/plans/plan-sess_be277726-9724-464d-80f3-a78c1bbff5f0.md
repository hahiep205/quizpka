## Phase 0 — Kiểm tra nền (read-only, không sửa gì)

1. **Grants live trên prod** (Management API `POST /v1/projects/qwbujoppcqpnummhpfbs/database/query`, không tốn Log Query):
   `select proname, proacl from pg_proc where proname in ('check_edge_rate_limit','increment_security_metric','increment_subject_attempt');`

## Phase 1 — DB: 3 migration mới (additive, backward-compatible)

Tên file theo convention `YYYYMMDDHHMMSS_name.sql` (timestamp > `20261002083000`), nộp prod qua SQL Editor/Management API + insert version vào `supabase_migrations.schema_migrations` (convention repo: prod áp tay).

**M1 — `20261004100000_edge_multi_gate_rpc.sql`**
- Tạo `check_edge_rate_limits(p_gates jsonb) returns jsonb` — security definer, `set search_path = public`, nhân bản logic fixed-window (FOR UPDATE + janitor 1%) của `check_edge_rate_limit`, duyệt mảng gates `[{bucket, limit, window_seconds}]` (tối đa 5), trả `{"allowed": bool, "results": [bool...]}` (false nếu bất kỳ gate nào chặn, các gate sau gate chặn vẫn chạy để không lệch counter).
- Idempotent `grant execute on function public.check_edge_rate_limit(text,integer,integer) to service_role;` (chạy vô điều kiện — an toàn dù live ACL đã có).
- Grants hàm mới: `revoke all from public, anon, authenticated; grant execute to service_role;` — theo đúng ma trận definer.

**M2 — `20261004100100_notification_digest_rpc.sql`**
- Tạo `get_my_notification_digest(p_include_unread boolean default false, p_dismissed_ids bigint[] default '{}', p_limit integer default 30) returns jsonb` — security definer, `set search_path = ''`, grant `authenticated`. Copy logic `auth.uid()` gating + truy vấn từ `list_my_notifications`/`count_my_unread_notifications` (migration 20260909210000). Trả 1 jsonb: `{unread_count, direct, items_all, items_unread}` — `direct` = unread+direct mới nhất mà id KHÔNG nằm trong `p_dismissed_ids` (chuyển vòng lặp "dismissed ẩn direct cũ" từ client xuống SQL), `items_*` = trang đầu 30 dòng của từng filter (chỉ build khi được yêu cầu).
- **Không revoke/drop** 2 RPC cũ (client loadMore cursor vẫn dùng; giữ rollback path).

**M3 — `20261004100200_admin_list_rpcs.sql`** — pattern theo `search_notification_recipients` (is_admin() gate, search_path = '', jsonb, clamp offset/limit):
- `admin_list_users(p_query, p_role, p_status, p_sort, p_desc, p_offset, p_limit) returns jsonb` — profiles LEFT JOIN user_learning_stats; search ilike email/display_name/id; filter role/status; sort theo `p_sort` ∈ {created_at, last_active, attempts, points, accuracy} (whitelist); trang 15–100 dòng; trả `{items, total, active_total, blocked_total, kpis}` — `kpis` tái tạo đúng các trường `computeAdminKpis` đang tính (`src/features/admin/lib/adminStats.ts:169–202`) bằng SQL aggregate (đếm total/active/blocked, new hôm nay/7d, tổng attempts, avg accuracy…). 1 request thay 4 request/trang + hết 416 (không còn offset stats bắt từ count profiles — `adminUsers.ts:16–22`).
- `admin_list_events(p_limit int default 3000) returns jsonb` — newest-first `user_activity_events` (bảng vốn bị cron giữ tối đa 3000 dòng — 20260910090000), trả mảng raw cùng shape select hiện tại để `parseActivityRows` dùng lại nguyên vẹn.
- `admin_list_attempts(p_limit int default 3000) returns jsonb` — tương tự cho `practice_attempts`.
- `admin_list_orders(p_since timestamptz, p_limit int default 500) returns jsonb` — orders `created_at >= p_since` (client truyền mốc 0h giờ local), join `products` để trả kèm `product_name` (bỏ luôn GET products riêng ở adminPayments.ts:66).
- Grants: revoke all từ public/anon/authenticated, grant `authenticated` (bên trong check `is_admin()`).

## Rủi ro & biện pháp

- **Proxy làm hỏng realtime/OAuth**: WS override là điểm rủi ro chính — verify trên dev build trước khi push (channel SUBSCRIBED + login Google end-to-end); storageKey bị ghim tường minh nên không mất session user hiện có.
- **RPC definer mới**: bám đúng ma trận (is_admin() gate, search_path='', revoke/grant tường minh, clamp limit); review SQL trước khi chạy trên prod.
- **Anomaly detection thu hẹp**: vẫn giữ full window 3000 events (đúng retention cap); attempts bound 3000 mới nhất (trước dump ~4000+ — chênh lệch không ảnh hưởng rules A1–A7 vốn nhìn theo user/event gần đây).
- **GSA/anon flow**: guard chỉ skip RPC khi thiếu session — không đổi grants, không mở anon execute (server vốn chặn bằng `is_active_user()`).
